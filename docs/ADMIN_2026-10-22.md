## 사용자가 Supabase 에서 할 일
1. Supabase Dashboard → SQL Editor → New query 에 `supabase/schema.sql` **전체**를 붙여넣고 **Run** (여러 번 실행해도 안전, `hd3d_` 객체만 만들고/고침, `cart_*` 는 건드리지 않음).
2. 그 외 설정 없음. owner(최고 관리자)는 SQL 이 `hyunjk11@daum.net` 계정에 자동으로 지정합니다 (그 계정이 이미 가입돼 있어야 함 — 이미 가입됨).
3. 하위 관리자는 게임 안 관리자 패널 → 「🛡 관리자」 탭에서 owner 가 이메일로 추가/삭제합니다 (상대가 먼저 가입해 있어야 함).
SQL 을 다시 실행하기 전까지 게임은 예전처럼 동작하고, 새 관리자 탭에는 "서버 업데이트 필요: schema.sql 을 다시 실행해 주세요" 가 뜹니다 (주문 승인/거절·우편 보내기는 그대로 가능).

## 기능
| 탭 | 내용 | 서버 함수 |
|---|---|---|
| 🧾 주문 관리 | 상태 필터(전체/대기/승인/거절/환불, 건수) · 이메일/닉네임 검색 · 20건씩 페이지 · 승인/거절(기존) · **환불**(확인 창+사유 필수 → 소유권 회수, 미수령 지급 우편 회수, 안내 우편) | `hd3d_admin_orders`, `hd3d_admin_refund` (+ 기존 approve/reject) |
| 👥 유저 관리 | 이메일/닉네임 검색 · 20명씩 페이지 · 가입/최근 접속/마지막 저장 · 별(일반/하드) · 영혼석/마력석/정수 · 최고 웨이브/출정 · 전직 · 유료 영웅 · 정지/관리자 표시 | `hd3d_admin_users` |
| 유저 상세 | 위 요약 + 유료 영웅 **지급/회수**(사유 필수) · 이 사용자에게 우편+보상 · **계정 정지/해제**(사유 필수) · 최근 주문/우편/관리 기록 | `hd3d_admin_user`, `hd3d_admin_grant_hero`, `hd3d_admin_revoke_hero`, `hd3d_admin_ban`, `hd3d_admin_unban`, `hd3d_admin_send_mail` |
| ✉ 우편 보내기 | 기존 (이메일 1명) | `hd3d_admin_send_mail` (서명 그대로, 제목 검사·기록 추가) |
| 📨 전체 우편 | 제목/내용/보상 → 받는 사람 수 확인 창 → 사용자마다 `hd3d_mail` 1행 (받기는 기존 `hd3d_claim_mail` = 서버에서 한 번만). 확인한 인원 수가 서버와 다르면 발송 안 함, 30초 쿨다운 | `hd3d_admin_broadcast_count`, `hd3d_admin_broadcast` |
| 📢 공지 | 작성/수정/게시·내리기, 시작·종료 시각(예약). 로그인 사용자는 게시 중 공지만 읽음 → 마을 입장 시 상단 배너, 닫으면 공지 id 를 localStorage(`hd3d_notice_seen`)에 기록 | `hd3d_notices` (RLS), `hd3d_admin_notice_save`, `hd3d_admin_notice_active` |
| 📜 활동 기록 | 모든 관리자 변경 작업(승인·거절·환불·우편·전체 우편·영웅 지급/회수·정지/해제·공지·관리자 추가/삭제) · 종류 필터 · 30건씩 페이지 | `hd3d_admin_log` (관리자만 select), `hd3d_admin_log_list` |
| 🛡 관리자 (owner 만) | 하위 관리자 이메일로 추가/삭제 (owner 삭제 불가, 정지된 계정 추가 불가) | `hd3d_owner_admins`, `hd3d_owner_add_admin`, `hd3d_owner_remove_admin` |

계정 정지: `hd3d_bans`. 정지되면 **진행 저장·닉네임 쓰기(RLS), 구매 신청(트리거+RLS), 우편 받기(RPC)** 가 서버에서 거부됩니다. 클라이언트는 마을 상단에 "⛔ 계정이 정지되었습니다 · 사유…" 안내, 동기화 표시 "계정 정지 · 서버 저장 중단", 상점 버튼 "⛔ 계정 정지", 우편함 안내. 진행은 이 기기에만 저장되고 해제되면 밀린 저장을 다시 올립니다. 관리자는 자기 자신·다른 관리자를 정지할 수 없습니다.

## 보안 메모 · 한계
- 관리자 버튼 표시는 서버 `hd3d_my_status` 결과로만 (구버전 서버면 owner 이메일). 실제 권한은 모든 RPC 가 다시 검사하고, 일반 사용자/익명은 모든 관리자 RPC·내부 함수 실행이 거부됨 (schema_pg 132개 검사).
- `search_path` 는 요청의 `public` 대신 기존 파일과 같은 `''`(빈 값) + 모든 객체 `public.`/`auth.` 정규화 — 더 엄격한 설정.
- 유저 검색은 이 게임 사용자(`hd3d_profiles`/`hd3d_progress` 행이 있는 계정)만 — 같은 프로젝트의 다른 게임 계정은 나오지 않음. 전체 우편 받는 사람도 같은 기준.
- 진행 요약은 사용자가 쓸 수 있는 저장 jsonb 에서 계산하므로 참고용 (형식이 이상하면 0 으로 안전하게 처리). 유료 영웅 소유권은 `hd3d_owned` 만 사용.
- 전체 우편은 발송 시점 사용자에게만 (이후 가입자 제외). 환불/회수는 영웅 소유권만 지우고 세이브의 영웅 레벨·장비는 남김(영웅만 잠김). 이미 받은 영혼석 등 재화는 회수하지 않음.
- 정지 중에도 게임은 이 기기에서 계속되며 진행은 로컬에만 저장됨 (해제 후 동기화). 정지를 클라이언트가 우회해도 서버가 저장·구매·받기를 거부.
- 관리 기록은 변경 작업만 (검색·조회는 기록하지 않음). 기록은 관리자도 지우거나 고칠 수 없음 (테이블 쓰기 권한 없음, SQL 편집기에서만 가능).
