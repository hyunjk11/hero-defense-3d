**주의할 점 (조사에서 발견)**
- 코드에서 "tower" 는 이미 **방어 타워** (`src/world/towers.js`, `G.towers`, `tests/tower.py`). 혼동 방지를 위해 코드 이름은 **`spire`** (`src/data/spire.js`, `hd3d_spire_*`, `G.spire`), 화면 이름만 "무한의 탑".
- 챕터 보스 능력 중 **타워만 노리는 것**(root 뿌리, snowball 눈덩이, chill, curse 저주, lavapool 용암 웅덩이)은 던전 맵(타워 없음)에서 아무 일도 안 함. **영웅에게도 통하는 것**: meteor(가장 가까운 영웅을 노림), dread(영웅 피해), summon, heal, crack(얼음 갑옷), enrage, shield(정령 보호막). → 탑 보스는 통하는 능력만 골라 만든 **변형(VARIANTS)** 으로.
- 지형/타워/길을 쓰는 몬스터(digger 굴착, bomber 자폭, siege 공성, charger 경로 질주)는 던전 맵에서 검증 안 됨 → 탑 풀에서 **제외** (T-3 에서 하나씩 확인 후 허용 여부 결정).
- `dungeon/boss.js` summon 이 `FLOORS[G.dg.floor]` 를 직접 읽음 → T-1 에서 같이 게터로.

## 1. 핵심 개념 & 던전 원정과의 차이

**한 줄**: "던전 원정"이 매일 도는 **정해진 5층 로그라이트**라면, "무한의 탑"은 **계정의 성장을 재는 끝없는 오르막** — 한 번 깬 층은 영구 기록, 5층마다 체크포인트, 층이 오를수록 강해지는 적과 주간 변형(어픽스)에 맞춰 **편성을 바꾸는** 컨텐츠.

| | 던전 원정 (기존) | 무한의 탑 (신규) |
|---|---|---|
| 목표 | 5층 완주 · 메달 파밍 | 최고 층 갱신 · 주간 순위 |
| 진행 | 매번 1층부터, 판이 끝나면 초기화 | **체크포인트(1·6·11·…)부터 이어 오르기**, 최고 기록 영구 저장 |
| 난이도 | 고정 (2.4~2.65배) | 층마다 지수 상승 → 언젠가 벽 (계정 성장 = 더 높이) |
| 변수 | 축복 운 | **층 어픽스** (가속·철갑·마법 저항…) — 주마다 같은 시드 → 모두 같은 탑 |
| 편성 | 아무나 4명 | 어픽스 때문에 **편성이 의미** ("이번 주 21~25층은 원거리 저항 → 세라·서윤 위주") |
| 보상 | 매일 반복 (메달 하루 최대 45) | **첫 돌파 보상(1회)** + 주간 기록 보상(작게) → 파밍 아님 |
| 보스 | 모르비아 1종 | **기존 보스 5종 로테이션** (10층마다), 회차가 돌수록 '각성' |
| 횟수 | 하루 3회 (서버) | 무제한 (서버는 스팸 방지 상한만, 결정 Q2) |
| 경쟁 | 없음 | 주간/전체 랭킹 (보상은 칭호만 — 치트 방지 한계 때문) |

## 2. 층 구조

### 2-1. 층 종류 (n = 층 번호)
| 종류 | 조건 | 구성 |
|---|---|---|
| 일반 | 나머지 | 웨이브 3개 (던전과 같은 길이 ≈ 50~70초) |
| 정예 | n % 5 == 3 (3, 8, 13, …) | 웨이브 2개 + 정예 2~4마리 (체력 ×2.5 · 크기 ×1.25 · 붉은 고리, 기존 hardE 수치 재사용) |
| 중간 보스 | n % 10 == 5 (5, 15, 25, …) | 호위 웨이브 1 + **해골 군주**(`boss`, 능력 없음 — 안정적) 또는 정예 해골 기사단(골렘 정예 3) 교대 |
| 대보스 | n % 10 == 0 (10, 20, …) | 호위 웨이브 1 + 로테이션 보스 (4장) · 돌파 후 **축복 3택1** |
| (체크포인트) | 보스 층(5의 배수) 돌파 | 다음 도전의 시작 지점으로 영구 등록 (서버) |

축복은 **보스 층(5의 배수) 돌파 때만** 3택1 (던전은 매 층) → 한 번 입장에 5층 구간 단위로 리듬. 일반 층 사이는 3초 "다음 층" 카드(자동 진행, 이때 생존 15% 회복 · 쓰러짐 30% 복귀 — 기존 `nextFloorHp`).

### 2-2. 난이도 공식 (서버·클라이언트 공용 상수, `src/data/spire.js`)
- 체력 배수 `hpMul(n) = 2.2 × 1.05^(n−1)`
- 피해 배수 `dmgMul(n) = 1.3 × 1.03^(n−1)`
- 웨이브당 마리 수 `count(n) = min(24, 14 + ⌊n/3⌋)` — 마리 수는 24에서 멈추고 이후엔 체력/피해만 오름 (Windows 데스크톱·태블릿 프레임 안정성. 던전은 현재 14~22마리)
- 보스 체력 = 기본 체력 × hpMul(n) × 0.55 (던전 5층이 1.4/2.6 ≈ 0.54 비율이라 같은 감각)
- 스폰 간격 `every = max(.4, .6 − n×.004)`, 웨이브 사이 `gap = 4`

| 층 | hpMul | dmgMul | 마리/웨이브 | 해골 군주(3200) 기준 보스 체력 | 예상 |
|---:|---:|---:|---:|---:|---|
| 1 | 2.20 | 1.30 | 14 | 3,872 | 던전 1층(2.4/1.4)보다 살짝 쉬움 |
| 5 | 2.67 | 1.46 | 15 | 4,706 | ≈ 던전 4층 |
| 10 | 3.41 | 1.70 | 17 | 6,007 | 기본 3명(장비 없음)의 벽 예상 |
| 20 | 5.56 | 2.28 | 20 | 9,784 | 장비 4명 + 강화 중간 |
| 30 | 9.06 | 3.06 | 24 | 15,938 | 전직·고유 장비 필요 |
| 40 | 14.75 | 4.12 | 24 | 25,961 | 상위권 |
| 50 | 24.03 | 5.53 | 24 | 42,287 | 최상위 (모르비아 1회차) |
| 60 | 39.14 | 7.44 | 24 | 68,882 | 사실상 벽 |

목표 분포(T-5 균형 시뮬 `tests/spbal.py` 로 조정): 기본 3명 무장비 ≈ 8~10층, 희귀 장비 4명 + 영구 강화 5 ≈ 20층, 전직+고유 ≈ 30~40층. 수치(1.05·1.03)는 시뮬 뒤 바꿀 수 있게 상수 한 곳에.

## 3. 파티 · 입장 · 체크포인트

- **파티**: 던전과 같은 고르기(4/5, 로즈·서윤은 서버 소유 확인, 버들 숨김). 고른 파티는 탑 전용 키 `hd3d_sppick` (어픽스 따라 원정과 다르게 둘 수 있게).
- **입장**: 탑 화면에서 시작 층 선택 = `1` 또는 돌파한 보스 층 + 1 (예: 최고 23층이면 1·6·11·16·21 선택 가능). 서버가 `hd3d_spire_start(p_from)` 에서 유효성 검사.
- **따라잡기 축복**: 높은 체크포인트에서 시작하면 그 전에 받았을 축복이 없어서 불리 → 시작 시 `min(3, ⌊(from−1)/10⌋)` 번 축복 3택1을 미리 받음 (21층 시작 = 2번).
- **한 번의 도전**: 시작 층부터 전멸/포기까지 계속 오름. 축복·게이지는 이 도전에서만.
- **이어하기**: 판 중 새로고침/창 닫기 = 그 도전 종료(던전과 같음). 단, **보스 층 돌파 시점마다 서버에 체크포인트 기록**(`hd3d_spire_ping`) → 브라우저가 죽어도 그때까지의 기록·첫 돌파 보상은 보존. 다음 입장은 새 체크포인트부터.
- **입장 횟수**: 무제한 권장 (보상이 첫 돌파 1회 + 주간 기록뿐이라 반복 파밍 가치 없음). 서버에는 스팸 방지 상한 **하루 30회** + 계정당 진행 중 도전 1개(새 시작 시 이전 것 포기 — 던전과 같음). → 결정 Q2.
- **연습 탑**: 게스트·오프라인·스키마 미실행 = 연습 (기록/보상 없음, 플레이는 가능) — 던전 fallback 과 같은 방식.

### 4-2. 첫 돌파 보상 (1회, 서버 상수 · 우편 지급)
- 보스 층 n = 5k 첫 돌파: **영혼석 `300 + 100k`** (5층 400 · 10층 500 · 20층 700 · 30층 900 · 50층 1,300 · 100층 2,300)
- 10의 배수 층 첫 돌파 추가: **던전 메달 `5 + n/10`** (10층 6 · 20층 7 · … · 100층 15)
- 100층 이후: 10층마다 메달 10 (영혼석 없음)
- 특별: 30층 칭호 `🗼 탑의 도전자`, 50층 칭호 `🗼 탑의 정복자` (기존 지갑 titles 재사용)

| 도달 | 누적 영혼석 | 누적 메달 | 영혼석 환산 합계(메달 1 ≈ 67) |
|---:|---:|---:|---:|
| 10층 | 900 | 6 | ≈ 1,300 |
| 20층 | 2,200 | 13 | ≈ 3,100 |
| 30층 | 3,900 | 21 | ≈ 5,300 |
| 50층 | 8,500 | 40 | ≈ 11,200 |
| 100층 | 27,000 | 105 | ≈ 34,000 (이론상) |
→ 보통 유저(20~30층) 총 ~5천 = 영웅 1명 단련 0→15(6.1만)의 10% 미만. **일회성 목돈**이라 인플레이션 없음.

### 4-3. 주간 기록 보상 (반복, 작게)
- 지난주 최고 층 W (그 주에 실제로 오른 층 — 체크포인트 시작이면 시작층−1 이후 실제 돌파분만 인정) 기준, 다음 주 탑 화면에서 **받기** (서버 lazy 정산, cron 불필요)
- 영혼석 `min(1500, W × 30)` + 메달 `min(25, ⌊W/5⌋ × 2)`
- 예: 주간 20층 → 영혼석 600 + 메달 8 / 주간 50층+ → 상한 1,500 + 25
- 최대치 주당 ≈ 3,200 상당 = 하루 ≈ 450 (강철 교환 하루 상한과 같은 규모) → 영혼석 부족을 **조금** 덜어 주되 기존 출정 수입(하루 수천)을 대신하지 않음.

### 4-4. 화폐
- **새 화폐 없이 던전 메달 재사용** (지갑·상점·우편·관리자 도구가 이미 서버 강제로 있음) — 결정 Q1.
- 던전 상점에 탑 상품은 추가하지 않음(1차). 칭호는 업적으로만.

## 6. 랭킹 · 기록 (Supabase, 서버 검증)

### 6-1. 테이블 (schema.sql 끝 '무한의 탑' 절, idempotent, RLS 본인 select 만 · 쓰기는 SECURITY DEFINER 함수만)
- `hd3d_spire_runs (id, user_id, token uuid unique, day date(KST), week date(KST 월요일), from_floor int, top_floor int, status active|done|abandoned, started_at, last_ping_at, last_ping_floor, finished_at)`
- `hd3d_spire_best (user_id pk, best_floor int, best_at timestamptz, cleared_bosses int /*보상 받은 최고 보스층*/, updated_at)`
- `hd3d_spire_weeks (user_id, week date, best_floor int, best_at timestamptz, claimed bool, primary key(user_id, week))`
- 함수:
  - `hd3d_spire_status()` → 최고 층, 체크포인트 목록, 이번 주 기록/내 순위, 지난주 미수령 보상, 오늘 시작 수
  - `hd3d_spire_start(p_from int)` → p_from ∈ {1} ∪ {5k+1 | 5k ≤ best} 확인 · 하루 상한 · 정지 거부 · 이전 active 포기 · token
  - `hd3d_spire_ping(p_token, p_floor)` → 보스 층(5의 배수)만 · 단조 증가 · 시간 검사 통과 시 last_ping 갱신 + best/week 갱신 + **첫 돌파 보상 지급(우편 + 메달 지갑)**
  - `hd3d_spire_finish(p_token, p_top)` → token 1회 · 위와 같은 검사 · 최종 기록
  - `hd3d_spire_rank(p_week date, p_kind 'week'|'all')` → 상위 50 (닉네임 = hd3d_profiles, 정지 유저 제외) + 내 순위
  - `hd3d_spire_claim_week(p_week)` → 끝난 주만 · 1회 · 영혼석 우편 + 메달
  - 관리자: `hd3d_admin_user` 에 spire{best, week, runs} 추가 · 기록 초기화 함수(관리자 로그)

### 6-2. 서버가 실제로 강제할 수 있는 것
| 검사 | 방법 |
|---|---|
| 시작 지점 위조 | p_from 은 서버가 아는 best 로만 허용 |
| 비정상적으로 빠른 등반 | 층당 최소 시간 `minSec(층) = 일반 25초 · 보스 40초` (던전은 20초) → 시작~ping/finish 경과 시간 ≥ 구간 층 합. 넘으면 층 수를 깎음(던전 `capped` 와 같음) |
| 한 번에 너무 많이 | ping 간격: 5층 구간마다 ≥ 125초. 1 도전에서 최대 +30층(그 이상은 다음 도전) |
| 재사용·동시 진행 | token 1회 · advisory lock · 계정당 active 1개 · 3시간 만료 |
| 보상 중복 | 첫 돌파 = `cleared_bosses` 보다 높은 보스층만 · 주간 = (user, week) claimed |
| 정지 유저 | 시작·정산 거부, 랭킹 제외 |

### 6-3. 강제할 수 **없는** 것 (한계 — 솔직하게)
- 전투는 클라이언트 시뮬레이션 → 개조 클라이언트가 "이기는 척" 하는 것 자체는 못 막음 (시간 하한을 지키며 천천히 올리면 통과). 영웅 스탯·장비도 클라이언트 세이브라 서버가 "이 전투력으로 40층은 불가" 를 판정할 근거가 없음.
- 대응: ① 랭킹 보상은 **칭호만** (재화 X) → 치트 이득 최소화 ② 첫 돌파/주간 보상에 상한 (위 4장) → 치트로 얻는 최대치가 정해져 있음 ③ 관리자 화면에서 이상 기록(층당 평균 시간이 하한 근처, 하루 +50층 등) 표시 + 기록 초기화/정지 ④ 결과 제출에 클라이언트 요약(파티·층별 시간·처치 수)을 **참고용 jsonb** 로 저장해 관리자가 볼 수 있게(검증 아님).

### 6-4. 랭킹 규칙
- 주간: KST 월 0시 ~ 일 24시. 정렬 = 주간 최고 층 ↓, 동률이면 **서버가 기록한 도달 시각** ↑ (클라이언트 시간 안 믿음).
- 전체: 최고 층 ↓, 도달 시각 ↑.
- 주간 순위 칭호(다음 주 표시): 1위 `🗼 탑의 지배자` · 2~10위 `🗼 탑의 정예` (claim_week 때 지갑 titles 에, 주가 바뀌면 교체). 유저 수가 적으므로 100위권 보상은 두지 않음.

## 9. 결정이 필요한 점 (추천 기본값)

1. **보상 화폐 — 던전 메달 재사용 vs 새 화폐(탑 조각)?**
   → **추천: 던전 메달 재사용.** 지갑·상점·우편·관리자가 이미 서버 강제로 완성돼 있어 스키마/버그 위험이 가장 적음. 새 화폐는 새 상점까지 필요.
2. **입장 횟수 — 무제한 vs 하루 N회?**
   → **추천: 무제한(서버 스팸 상한 하루 30회).** 보상이 첫 돌파 1회 + 주간 기록뿐이라 반복해도 이득이 없고, "벽에 계속 도전"이 탑의 재미. 하루 3회로 묶으면 원정과 같은 느낌이 됨.
3. **쓰러진 영웅 복귀 규칙 — 던전과 같이 매 층 30% 복귀 vs 보스층 돌파 때만 복귀?**
   → **추천: 1차는 던전과 같이(매 층 30%)** — 코드 재사용·균형 데이터가 이미 있음. 탑만의 긴장감이 부족하면 T-5 시뮬 뒤 "보스층에서만 복귀" 어픽스(저주 계열)로 실험.
4. **랭킹 공개 범위 — 주간+전체 vs 전체만?**
   → **추천: 주간 + 전체 둘 다, 보상은 칭호만.** 주간은 늦게 시작한 유저도 경쟁 가능, 재화 보상이 없어 치트 동기 낮음. 서버 검증 한계(6-3) 때문에 재화형 순위 보상은 하지 않음.
